# SciFact 回退率实验：执行前协议 v1

本协议在本轮新增模型请求之前写入。目标：在不改变全零回退语义、不删题、不降低检索质量的前提下，降低非思考重排回退率，形成可审计的开发集工程结果。结果无论正负都记录，不以简历目标倒推指标。

## 冻结条件

- 原 807 development、现有 FTS+RRF 100-depth 候选、title+prefix_600、只重排 top-10、tail 完整保留、同一模型、temperature=0、max_tokens=1024、enable_thinking=false。
- 对照使用 `runs/scifact-nonthinking-development807-v1/` 已有结果，不重复消费原思考型请求。
- 无数据库、embedding、答案生成、native 或 test 访问；无自动修补、补分、强制正分、挑题、自动重试。
- 所有 0..10 分数允许为 0；全部为 0 仍按原规则回退，不靠改变回退定义获得改善。

## 两项预先限定的消融

1. **keyed_v1（仅输出契约）**：保留原“回答问题”的评分语义，输出 `scores` 对象，以每个 passage ID 为键；必须完整覆盖且唯一，分值范围不变。
2. **relevance_v1（输出契约＋相关性 rubric）**：使用同样 keyed 输出，明确输入可以是问题或事实断言；评分是证据相关性，不是断言真假/是否能直接回答问句；支持与反驳证据均可相关。无相关证据时可以全零，不保证每题有正分。

不用供应商 JSON Schema 或 JSON mode，不混入接口能力、重试和请求次数差异。应用旧 prompt 为默认，新增版本均显式 opt-in。

## 固定阶段与停止规则

- 筛选：冻结原 development 顺序前 100 题，两版本各 100 次；可分先 5 再 95 冒烟，但如成功结果必须复用、不重复发送。本轮采用直接 100（失败仍计分）。
- 开发筛选门槛：相对同题旧非思考 baseline，nDCG@10 点估计下降不超过 **0.01**，且回退次数严格减少。
- 多个版本达门槛：优先回退数少者，再按 nDCG@10 高者，再按名称字典序。无版本达门槛则停止扩大，记录失败，不加第三个候选。
- 固定所选版本，对余下 707 development 扩展，复用其前 100 结果。因此本轮最多 **907 次新增请求**。4 workers，SDK retries=0，timeout=60s。
- 完成全 807 后不再次选参：检验点估计 nDCG@10 仍不低于旧 baseline−0.01，并报告逐题配对 bootstrap 的 nDCG 差值区间。**点估计门槛不等于已证明统计非劣**。

## 报告项

- full807、screen100、remaining707 分开报告，明确后两者也都属于已使用 development，不能称独立/未见测试集；test 300 保留。
- 总回退、全零、契约/格式错误、请求失败分别计数；全部题目计入 nDCG@10、MRR@10、Recall@10/100。
- 有效输出但相同分数导致顺序不变的比例另列，不把“没回退”等同“排名改善”。
- 固定原 query 顺序，配对 bootstrap 10,000 次、seed=20261020，报告 95% percentile interval；dev 筛选后区间仅为描述性，不抵消选择偏差。回退差值也按同样成对 query 重采样。
- 请求/响应/usage/CNY 估价（非实扣）、输入/脚本 hashes、运行快照、0 reasoning 验证、head/tail 与 metric 复算。
- 耗时仅 rerank-only，历史对照非严格在线 E2E/并发压测。不把错误减少算成业务成功率或问答准确率。
- 简历只写实际达成的数字和 SciFact development 范围，面试材料记录机制假设、消融、失败案例、质量权衡及局限。
