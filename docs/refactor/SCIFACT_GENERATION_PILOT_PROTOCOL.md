# 生成端受控小实验协议：evidence_contract_v1（仅计划，未调用）

## 目的和范围

检验一个假设：**显式约束结论与实体、干预、终点、时间及证据范围一致，能否减少“引用事实正确、最终结论越界”的回答，同时保留有证据时的正常回答能力。**

本轮只完成12个案例归因、候选提示词和离线请求计划。尚无候选回答或效果数字。后续执行需明确启动本计划，不把“继续分析”当作无限付费API授权。应用默认、冻结200份回答、原金标/AI评分/v1协议不改。

## 一项改动，不是新Agent框架

唯一实验变量：在原 `generation.SYSTEM_PROMPT` 后附加 `configs/prompts/answer_evidence_contract_v1.txt`，版本名 `evidence_contract_v1`。原system前缀、user消息/claim、检索上下文顺序与内容、模型及参数全部相同。不是同时改top_k、重排、生成模型、temperature或思考参数。

候选要求输出短的 `Decision / Scope / Evidence / Limits`，先对齐必要条件，并给出公开可核对的证据说明；不要求暴露内部逐步思维过程，也不新增第二次反思/评审API调用。它允许合理文本推断，不以“没有独立RCT/直接生化实验”为由机械拒答；对定义分歧保留不确定性。候选只是一个待验证的设计，不是已证明的改进。

底座统一使用**新重排 relevance_v1 的保存top4完整chunks**；这里比较的是 `baseline_generation` vs `evidence_contract_v1`，**不是再比较旧/新重排**。使用官方deepseek-flash、temperature=.2、max_tokens=2048、stream=false、SDK retries=0、timeout=60s、单线程。不得补入参考文献、外部常识或来源全文中未发送的内容。

## 两阶段、最多64次生成请求

### A. 12题机制诊断/回归：24次，两个生成版本各12

题号固定为 0、14、24、35、37、44、61、81、96、98、109、119。这是看过历史结果后选择的目的性开发样本，不是随机样本，不报告总体错误率。

- 4个明确修复目标：q24 时间/终点替换，q35 复合干预单因子归因，q81 结论标题与操作范围不一致，q96 无证据的外部细节。这些是**给定文本和本协议下的生成约束问题**，不是宣称医学命题已被证明为假。
- 4个防退化控制：q0 合理拒答，q37 有直接反向证据应正常反驳，q44 本地文档缺结果应保留不足，q109 明确区分细胞定位与下游作用组织。不能靠全部改NEI过关。
- 4个歧义探针：q14 代谢机制用语，q61 个体感染性/人群模型，q98 终点与趋势，q119 药物类别量词/混合标题抽取。须说明范围/证据缺口，不为追分预定唯一医学标签；争议保留为uncertain。

旧B回答仅供历史诊断。**重新生成同条件baseline**与候选配对，不能用历史基线对候选的差值忽略随机性和供应商时间漂移。每题两版本奇偶交替先后，无自动重试/格式修复/补跑；失败、截断、空答均保留。

A阶段进入B的条件（执行前固定）：
1. 候选在4个修复目标中至少3个满足预列证据范围要求，且4个控制均不退化；
2. 相对同期baseline至少1题明确改善，明确退化0题；候选只是重复baseline正确答案不算改善；
3. 不确定裁决不能算胜利；4个歧义题完整报告，不当作4个有利成功样本；
4. 所有24次请求成功、非截断，candidate不得出现新的无证据关键断言。

若A不通过，停止，不试第二版prompt、不降低门槛。记录机制未成立或基线随机变化即可；不必为简历制造胜利。

### B. 新生成开发20题：40次，两个生成版本各20

仅A通过后执行。题号按冻结807条development原顺序 `[100:120]`（第101～120条）确定，不按相关性/难度/完成速度挑选。离线计划会记录实际ID和64份完整请求预览；这些20题不与原100题重叠。

这些题此前参与过检索/重排开发，**不是从未使用的holdout，不是test，也不保证预训练未见**；只是尚未进入原200份回答生成的新增开发cohort。计划生成过程中只在程序内读取其claim/上下文组装请求，不提前给主助手展示内容或生成答案。没有参考标签注入请求，不新增gold修订。

最多新增模型调用：A 24＋B 40＝64，且不是本轮已发生调用。A未过时B的40次请求虽然已有预览，也不得执行。

## 评审与指标：由主助手做AI评审

按用户偏好由主助手负责，不要求用户全面人审，也不冒充独立盲评/领域专家验证。评审以**实际发送的上下文**为范围，区分false和uncertain。尽可能先逐答案判断，再看配对差异；若主助手已看到版本/答案或诊断案例，明确记录非盲，不虚构独立性。新增外部judge调用不在64次生成额度内，默认不调用。

每份答案记录：
- 原命题的关键条件及其上下文证据；允许语义等价、合理逻辑推断，不要求逐字命中。
- 最终结论与范围一致性：acceptable / unacceptable / uncertain；缺依据、错终点/时间/实体/操作、相互矛盾的标题记unacceptable；定义合理分歧记uncertain，不强算错或对。
- 无依据关键断言、必要支持片段与遗漏点；不得因候选更短而漏评事实，或只评它主动给了引用的陈述。
- 片段支持率（含不确定上下界）、引用支持率、断言引用覆盖率、必要条件覆盖率、适当拒答/误拒答及各自分母。
- 格式合规单列。多了四个标题不能自动记为答案变正确；格式不合格不自动重试。

沿用AI审计v2组合引用解析；对多源联合支持另记joint-support，不把某个来源未单独支持整句的所有场景一律称幻觉。单来源口径与联合口径均列，不能混换分母来宣布改善。原封存标签一致率只作参考敏感性，不作为唯一正确性真值。

对B的主指标：query级“结论与证据范围一致”率，uncertain给上下界；配对改善/下降/相同/不确定四类，并报告全部20题与配对bootstrap描述性95%区间（seed=20261020，10000次）。不把A的诊断12题混入B凑显著性。

B的工程点估计目标：候选acceptable下界≥85%（至少17/20）；必要条件覆盖率≥90%、片段支持下界与引用完全支持率≥95%、有充分上下文题误拒答≤5%；零分母报NA，不能按通过处理。相对baseline净明确改善至少2/20、无新增无依据关键断言。所有指标和失败一并报告，不单挑结论一致率或拒答率。**这些是补充协议的AI工程筛选目标，不是原v1人工/科学准确率门槛被“验收通过”。**

20题很小，即使点估计达标也不保证区间排除0。只有配对区间支持、无明显质量退化且口径一致时，才考虑后续更大cohort确认；否则仅写pilot观察，不写简历“最终回答质量已提升”。不以修过同一12题作为泛化证据。

## 成本与延迟

保留每次原始请求/response、usage、finish_reason、计时、started/finished；区分input/completion/reasoning（reasoning若已包含在completion不能双计）。候选额外system文本可能增加输入、输出长度和延迟，必须如实报告。

本轮计划不读取密钥、不计算虚构账单。执行时需独立核对官方价格/时段，未知为null而不是0；外部AI/主对话费用与应用生成API费用分开。不能套用硅基价格。记录generation-only P50/P95及相对值，候选P50>baseline 1.25倍或输入+输出tokens>1.25倍时标注效率代价，不把质量收益讲成无代价；这是权衡提示，不是偷偷改token上限。

## 防止事后选题/改标签

- casebook只用于定位和A回归；不是新金标。
- reference/范围争议另存，不修改封存gold、上传review或历史scores。
- 候选prompt、题号、请求、来源/脚本/协议hash先保存，再执行；任何实质变动都新版本。
- 若环境/模型配置不符、原文件hash变化或出现无法确定的调用状态，停下记录，不隐式重试。
- 本计划没有执行器；仅离线构建64份请求预览，不存在`--execute`或自动启动API的开关。未来实现执行器时需继续遵守两阶段门禁。
